ACME Profiles & Defaults
Saved certificate authorities, reusable DNS credentials and the default key type

Default key type

RSA2048
Used for new certificates when no key type is picked. EC keys are smaller and faster; RSA is the most compatible. Existing certificates keep their key type on renewal.

Saved certificate authorities

Add a private ACME server, ZeroSSL or Google (External Account Binding) once and pick it when requesting certificates. Each saved CA keeps its own ACME account, also when two of them use the same directory URL and email. The EAB key is never shown again after saving.

Saved CADefault for new certificatesActions

The default CA is used for new certificates that are requested without choosing a saved CA: the quick requests (New site page, New proxy rule, "Add a certificate"; they still need the ACME email of the ACME page) and API requests without caProfile, whatever CA they name (caProfile=none keeps the named CA). It is preselected in the certificate request dialog. No default: such requests use the CA chosen on the ACME page, as before. Existing certificates are never moved by this setting.

Already using one CA for everything? This saves the CA chosen on the ACME page (with its email, custom URL and EAB key) as a saved CA that keeps using the existing ACME account. Nothing else changes: the settings of the ACME page stay, no certificate is moved and no default is set.

CA of existing certificates

Move a certificate to a saved CA without requesting it again: the certificate stays as it is, and its next renewal (automatic or "Renew now") goes to the CA chosen here. "No saved CA" keeps the CA the certificate was last issued by. A saved CA decides by itself whether TLS errors of its server are ignored, and the ACME profile name of the previous CA is not carried over. Only certificates issued by ACME on this server are listed; uploaded certificates cannot be assigned.

Saved DNS credentials

Create profiles from the certificate request dialog ("Save these credentials as a reusable profile"), or paste the provider credentials here as JSON. Secrets are stored in the system database like the per-certificate DNS credentials and are never shown again. The default profile is pre-selected when you pick a DNS challenge and is used when a certificate has no credentials of its own.
