Graduated response

Log, challenge or block: borderline visitors can solve a CAPTCHA once instead of getting a 403. Off while the challenge threshold is 0.

Must be lower than the block threshold. With a block threshold of 5, a value of 3 challenges a lone warning or error rule and still blocks a critical one.

How long a solved challenge keeps the visitor in the pass band (1 - 1440). The pass is tied to the visitor's IP address and browser.

The challenge uses the CAPTCHA provider configured on the proxy rule (the same page and provider as "Require CAPTCHA"). It is only shown to page navigations (GET requests that accept HTML). A rule without a CAPTCHA provider, and API or script clients, are blocked in the challenge band instead. Detection-only mode never challenges.

How the bands work
A visitor whose score is between the challenge threshold and the block threshold gets a CAPTCHA page once, and passes for the validity time after solving it. Scores at or above the block threshold are still blocked, and a solved challenge never opens that band. Challenged requests do not count towards the automatic ban.

What to do with each kind of leak

Applies to every proxy rule that has the WAF on; profiles and single proxy rules can override each group. Every group is off until you choose otherwise.

What it can and cannot do
  • Block replaces the response with a generic 502 page, but only when the leak is inside the inspected window (the first N KiB of the body). A leak further down is not seen. Log only never changes a single byte.
  • Streams are never held back: Server-Sent Events, gRPC, WebSocket and other upgrades, partial content (206), chunked responses of unknown length and non-text content are passed through untouched.
  • gzip and deflate are decoded for inspection with a hard cap (never more than the window is decompressed); Brotli and zstd responses are not inspected.
  • Both Block and Strip only act when the WAF of the proxy rule is in Block mode; in detection-only mode they are logged as "would block".
  • Secrets with a checksum (GitHub tokens) or a pair (AWS key and secret) are blockable; weaker hits (a Stripe test key, a JSON password value) are only ever logged.
  • A leaking server is not a misbehaving client, so blocked responses never feed the automatic ban.

Defaults for every proxy rule

On top of the Core Rule Set. It needs the global WAF policy to be enabled. Settings stack: these defaults, then a profile, then the proxy rule.

What it checks
Structural limits (nesting depth, key / array / string sizes, XML DOCTYPE and entity blocking, query and header limits), allowed methods and content types per path, and optional OpenAPI 3 validation. Each layer can be set to Log only (events, nothing rejected) or Block. Not covered: GraphQL query cost, gRPC and response schemas.
