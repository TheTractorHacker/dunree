Cluster / HA

Run two or more Dunree nodes behind a floating IP or a load balancer: they share one secret, and a primary can copy its configuration to followers.

The shared secret makes visitor sessions (CAPTCHA, load balancer stickiness) valid on every node. Followers pull a signed, encrypted snapshot of the primary's proxy configuration. Standalone nodes (the default) are unaffected. Fleet, the other tab, adds per-node credentials, groups and staged rollouts; a node uses one of the two modes.

Floating IP
Each node keeps its own static address. keepalived (VRRP) puts one more address, the floating IP, on the node that is healthy, and moves it when that node or Dunree on it stops answering. Dunree writes the keepalived configuration and the commands for you and shows the status. It never changes keepalived, your firewall or the network settings of this host: you run the commands yourself. Guide: docs/guides/floating-ip-keepalived.md.

Two nodes keep their own addresses. A third address in the same subnet moves to the node that is healthy, and your firewall always points at it. Off by default.

Split brain: more than one node holds the floating IP The nodes cannot see each other's VRRP messages, so traffic flips between them. Check that both run the same generated configuration (same settings fingerprint), that they are on the same VLAN, and that a host firewall does not drop VRRP (protocol 112).

The floating IP

A third address that no device uses, in the same subnet as the nodes and outside the DHCP range of your router. Do not create a fixed-IP reservation for it. Your firewall's port forward points at this address.

The nodes

Each node keeps the static address it has today. The node with the highest priority normally holds the floating IP. Every node finds itself in this list by its own address, so nothing else has to be typed on the other node.
