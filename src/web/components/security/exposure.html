Network exposure

Two optional limits that keep this Zoraxy from being used to reach, or be reached from, places it should not. Both are off until you configure them: nothing changes for an existing setup. This does not configure your firewall; keep your firewall rules, this is a second layer.

Destination restriction

Applies to the upstream test, port and IP scan, uptime monitor checks, the web terminal and the HTTP forward proxy. They then refuse loopback, link-local, cloud metadata (169.254.169.254, fd00:ec2::254), multicast and unspecified addresses, including their IPv6 transition forms, and, when the list below is not empty, every address outside it. The name is resolved once and the checked address is the one that is dialled. Note that uptime checks of an upstream on 127.0.0.1 or outside the list will fail while this is on: list those upstreams below first (the warning box shows what would be refused now).

A network or address (CIDR or IP), optionally followed by a space and ports (443 or 8000-8100, comma separated), or written as 10.0.0.5:443. When this list is not empty, a proxy rule, upstream, virtual directory or default site target outside it is refused when it is saved, even with the switch above off. Names in a target are resolved at save time. An empty list means no restriction. Loopback is only reachable when listed here. Metadata and link-local addresses are never allowed.

Admin panel allow-list

Only these networks may connect to the admin port (). Everything else gets "403 Forbidden". Empty = no limit (default). The API, plugin and Fleet or cluster endpoints on the admin port are covered too, so list the hosts that use them. Requests that a proxy rule of this Zoraxy forwards to the admin port are refused while a list is set. Plugins that use the loopback port of an HTTPS admin panel are not affected.

Your address, , must be in the list: a list without it is not saved, so you cannot lock yourself out from here. If you are locked out anyway, stop Zoraxy and start it once with -reset_admin_allowlist, then remove the flag. 0.0.0.0/0 is refused.
