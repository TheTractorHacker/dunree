How the check works, and rotating a secretSeveral values, patterns, paths and what is kept secret.
  • Every rule must pass, or at least one if you choose that for the site. A rule passes when any one of its values matches.
  • Must not: the "must not" choices turn a rule around. "Be absent" refuses requests that carry the header at all. With "at least one rule", a "must not" rule alone lets in everyone who leaves that header out.
  • Remove before forwarding takes the header off requests that are let in, so the secret does not reach your app. It only works inside the rule's path: a rule limited to /admin leaves the header on every other path. It also applies to the addresses that skip the check.
  • Addresses that skip the check are compared with the client address this site's access rule sees. Forwarded-for headers only count when that access rule trusts them.
  • Rotate a secret without downtime: add the new value on a second line, switch your CDN over, then remove the old line.
  • Secrets stay secret. They are never logged or shown again. Leave the value box empty to keep what is stored.
  • Only below a path limits the rule to that part of the site, for example /admin. Empty means the whole site.
