Zoraxy only asks a CrowdSec server (its Local API) which addresses to refuse. It does not install or run CrowdSec for you. Three steps:

  1. Install CrowdSec on a server (see 1a and 1b). It can be this machine or another one.
  2. Create a bouncer key for this Zoraxy on that server.
  3. Paste the address and the key in the Connection card below, press Test connection, and start in Log only mode.

Use one key per Zoraxy instance, and make sure Zoraxy can reach the server address. The commands come from the CrowdSec documentation; read them before you run them. Every release also ships a helper script, a Docker file and a README (release page of your version); Zoraxy never runs them.

1a. Install on Debian or Ubuntu

Careful: the first command downloads a script from the internet and runs it as root (curl | sh). Read it first if you can: open https://install.crowdsec.net in a browser, or add the repository by hand as the CrowdSec documentation describes.

curl -s https://install.crowdsec.net | sudo sh
sudo apt install crowdsec

The first line adds the CrowdSec package repository by running a script from crowdsec.net; the documentation also describes adding the repository by hand if you prefer to inspect it first.

1b. Or run it in Docker (compose file)
# compose.yaml  (optional: create ./crowdsec/acquis.yaml first, see step 4b; remove that line if you skip log reading)
services:
  crowdsec:
    image: crowdsecurity/crowdsec
    restart: always
    ports:
      - 127.0.0.1:8080:8080
    environment:
      COLLECTIONS: "crowdsecurity/linux"
    volumes:
      # optional log reading: create ./crowdsec/acquis.yaml and un-comment both lines
      # - ./crowdsec/acquis.yaml:/etc/crowdsec/acquis.yaml
      # - /path/to/your-zoraxy-log-folder:/var/log/zoraxy:ro
      - crowdsec-db:/var/lib/crowdsec/data/
      - crowdsec-config:/etc/crowdsec/
volumes:
  crowdsec-db:
  crowdsec-config:

Replace /path/to/your-zoraxy-log-folder with your Zoraxy log folder (default ./log next to the Zoraxy program). Inside the container that folder appears as /var/log/zoraxy. Port 8080 is published on 127.0.0.1 only, as in the documentation; when Zoraxy runs on another machine publish it on an address Zoraxy can reach and keep it off the internet.

2. Create the bouncer key
sudo cscli bouncers add zoraxy-$(hostname)

Prints the key once; copy it at once. Run it where CrowdSec runs (inside the container for Docker; the documentation page for Docker does not show the exact command for that, so it is not given here). Use a different name for each Zoraxy instance.

3. Paste address and key

In the Connection card below enter the LAPI address (the documentation examples use http://127.0.0.1:8080) and the key, press Test connection, then save. Leave the mode on Log only until the recent matches look right.

Optional: let CrowdSec read Zoraxy's request logs

This step is optional. CrowdSec has no built-in parser for the log type zoraxy, so without a parser of your own (see the CrowdSec guide) the lines are read but not understood and no scenario fires. The community blocklist and every other decision your LAPI holds work in Zoraxy without this step. Zoraxy writes one file per month named zr_<year>-<month>.log (for example zr_2026-9.log, no leading zero) in its log folder.

Option A. CrowdSec installed from packages
sudo mkdir -p /etc/crowdsec/acquis.d
sudo tee /etc/crowdsec/acquis.d/zoraxy.yaml >/dev/null <<'EOF'
filenames:
  - /path/to/your-zoraxy-log-folder/zr_*.log
labels:
  type: zoraxy
EOF
sudo crowdsec -t && sudo systemctl restart crowdsec

Replace /path/to/your-zoraxy-log-folder with your Zoraxy log folder (default ./log next to the Zoraxy program; use its full path). The last line checks the configuration and restarts CrowdSec, as in the documentation.

Option B. CrowdSec in Docker
# ./crowdsec/acquis.yaml   (mounted at /etc/crowdsec/acquis.yaml by the compose file above)
filenames:
  - /var/log/zoraxy/zr_*.log
labels:
  type: zoraxy

The path in this file is the one inside the container (where the compose file mounts your log folder), not the path on the host. Then run docker compose up -d (recreates the container).

Manage bans on the CrowdSec serverSee what is banned, ban or unban an address and read the alerts without leaving Zoraxy. Needs a machine login created once on the CrowdSec host.
  1. Run this on the CrowdSec host. It prints a machine id and a password once.
  2. Paste them below.
sudo cscli machines add zoraxy-admin --auto -f -

Save the server address above first. Zoraxy stores the login encrypted, sends it only to that address and records every change in the security audit log. The machine can ban and unban any address, so use one just for Zoraxy; revoke it with sudo cscli machines delete zoraxy-admin.
