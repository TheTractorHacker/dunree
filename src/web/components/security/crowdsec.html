CrowdSec

Use a CrowdSec Local API (LAPI) that you run as a block list for this proxy. Zoraxy keeps the ban decisions in memory (stream mode) and checks every visitor address against them. Off until you switch it on, and it starts in Log only mode: matches are counted and logged, nobody is blocked. With two Zoraxy instances, point both at the same LAPI. Detection (feeding CrowdSec your logs) and reporting alerts back to CrowdSec are not part of this; see the CrowdSec guide.

Set up CrowdSec (not installed yet?)

Zoraxy does not install CrowdSec and never runs installers from this page. It is only the bouncer: it asks a CrowdSec Local API (LAPI) for the addresses to refuse. CrowdSec itself runs on a server of your choice. Three steps:

  1. Install CrowdSec on a server (below). It can be this machine or another one.
  2. Create a bouncer key for this Zoraxy on that server.
  3. Paste the address and the key in the form below, press Test connection, and start in Log only mode.

Use one bouncer key per Zoraxy instance. The LAPI address must be reachable from Zoraxy (check firewalls and where the port is published). The commands below come from the CrowdSec documentation and were not run by Zoraxy; read them before you run them.

Each Zoraxy release also ships a helper script crowdsec-setup.sh (Debian/Ubuntu, asks before every change, has --dry-run), a Docker file crowdsec-docker-compose.yml and CROWDSEC-README.md. Download them from the release page of the version you are running and run them yourself on the CrowdSec machine; Zoraxy never runs them.

1a. Install on Debian or Ubuntu

Careful: the first command downloads a script from the internet and runs it as root (curl | sh). Read it first if you can: open https://install.crowdsec.net in a browser, or add the repository by hand as the CrowdSec documentation describes.

curl -s https://install.crowdsec.net | sudo sh
sudo apt install crowdsec

The first line adds the CrowdSec package repository by running a script from crowdsec.net; the documentation also describes adding the repository by hand if you prefer to inspect it first.

1b. Or run it in Docker (compose file)
# compose.yaml  (optional: create ./crowdsec/acquis.yaml first, see step 4b; remove that line if you skip log reading)
services:
  crowdsec:
    image: crowdsecurity/crowdsec
    restart: always
    ports:
      - 127.0.0.1:8080:8080
    environment:
      COLLECTIONS: "crowdsecurity/linux"
    volumes:
      # optional log reading: create ./crowdsec/acquis.yaml and un-comment both lines
      # - ./crowdsec/acquis.yaml:/etc/crowdsec/acquis.yaml
      # - /path/to/your-zoraxy-log-folder:/var/log/zoraxy:ro
      - crowdsec-db:/var/lib/crowdsec/data/
      - crowdsec-config:/etc/crowdsec/
volumes:
  crowdsec-db:
  crowdsec-config:

Replace /path/to/your-zoraxy-log-folder with your Zoraxy log folder (default ./log next to the Zoraxy program). Inside the container that folder appears as /var/log/zoraxy. Port 8080 is published on 127.0.0.1 only, as in the documentation; when Zoraxy runs on another machine publish it on an address Zoraxy can reach and keep it off the internet.

2. Create the bouncer key
sudo cscli bouncers add zoraxy-$(hostname)

Prints the key once; copy it at once. Run it where CrowdSec runs (inside the container for Docker; the documentation page for Docker does not show the exact command for that, so it is not given here). Use a different name for each Zoraxy instance.

3. Paste address and key

In the form below enter the LAPI address (the documentation examples use http://127.0.0.1:8080) and the key, press Test connection, then save. Leave the mode on Log only until the recent matches look right.

4. Let CrowdSec read Zoraxy's request logs (optional)

This step is optional. CrowdSec has no built-in parser for the log type zoraxy, so without a parser of your own (see the CrowdSec guide) the lines are read but not understood and no scenario fires. The community blocklist and every other decision your LAPI holds work in Zoraxy without this step. Zoraxy writes one file per month named zr_<year>-<month>.log (for example zr_2026-9.log, no leading zero) in its log folder.

4a. CrowdSec installed from packages
sudo mkdir -p /etc/crowdsec/acquis.d
sudo tee /etc/crowdsec/acquis.d/zoraxy.yaml >/dev/null <<'EOF'
filenames:
  - /path/to/your-zoraxy-log-folder/zr_*.log
labels:
  type: zoraxy
EOF
sudo crowdsec -t && sudo systemctl restart crowdsec

Replace /path/to/your-zoraxy-log-folder with your Zoraxy log folder (default ./log next to the Zoraxy program; use its full path). The last line checks the configuration and restarts CrowdSec, as in the documentation.

4b. CrowdSec in Docker
# ./crowdsec/acquis.yaml   (mounted at /etc/crowdsec/acquis.yaml by the compose file above)
filenames:
  - /var/log/zoraxy/zr_*.log
labels:
  type: zoraxy

The path in this file is the one inside the container (where the compose file mounts your log folder), not the path on the host. Then run docker compose up -d (recreates the container).

Not offered: a "Detect" button for a local CrowdSec. The documentation does not list a public health or version address on the Local API, so Zoraxy has nothing it may call without a key. Use Test connection.

Manage CrowdSec

CrowdSec has no web page of its own on the server; its web interface is the free online Console at app.crowdsec.net. This panel lets you manage the local CrowdSec directly from here: see what is banned, ban or unban an address, and read the alerts (what was detected and why). It needs a separate login of a CrowdSec "machine", created once on the CrowdSec host. Zoraxy stores it encrypted, only sends it to the LAPI address it was entered for, and records every change in the security audit log.

1. Run this on the CrowdSec host. It prints a machine id and password once. 2. Paste them below.

sudo cscli machines add zoraxy-admin --auto -f -

Save the LAPI address above first. The machine can ban and unban any address, so use one machine just for Zoraxy; remove it on the CrowdSec host with sudo cscli machines delete zoraxy-admin to revoke access.
