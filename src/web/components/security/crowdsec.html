New to CrowdSec? Set it up in three stepsInstall CrowdSec, create a key for this Dunree, paste address and key below. Dunree never installs or runs it for you.

Dunree only asks a CrowdSec server (its Local API) which addresses to refuse. It does not install or run CrowdSec for you. Three steps:

  1. Install CrowdSec on a server (see 1a and 1b). It can be this machine or another one.
  2. Create a bouncer key for this Dunree on that server.
  3. Paste the address and the key in the Connection card below, press Test connection, and start in Log only mode.

Use one key per Dunree instance, and make sure Dunree can reach the server address. The commands come from the CrowdSec documentation; read them before you run them. Every release also ships a helper script, a Docker file and a README (release page of your version); Dunree never runs them.

1a. Install on Debian or Ubuntu

Careful: the first command downloads a script from the internet and runs it as root (curl | sh). Read it first if you can: open https://install.crowdsec.net in a browser, or add the repository by hand as the CrowdSec documentation describes.

curl -s https://install.crowdsec.net | sudo sh
sudo apt install crowdsec

The first line adds the CrowdSec package repository by running a script from crowdsec.net; the documentation also describes adding the repository by hand if you prefer to inspect it first.

1b. Or run it in Docker (compose file)
# compose.yaml  (optional: create ./crowdsec/acquis.yaml first, see step 4b; remove that line if you skip log reading)
services:
  crowdsec:
    image: crowdsecurity/crowdsec
    restart: always
    ports:
      - 127.0.0.1:8080:8080
    environment:
      COLLECTIONS: "crowdsecurity/linux"
    volumes:
      # optional log reading: create ./crowdsec/acquis.yaml and un-comment both lines
      # - ./crowdsec/acquis.yaml:/etc/crowdsec/acquis.yaml
      # - /path/to/your-dunree-log-folder:/var/log/dunree:ro
      - crowdsec-db:/var/lib/crowdsec/data/
      - crowdsec-config:/etc/crowdsec/
volumes:
  crowdsec-db:
  crowdsec-config:

Replace /path/to/your-dunree-log-folder with your Dunree log folder (default ./log next to the Dunree program). Inside the container that folder appears as /var/log/dunree. Port 8080 is published on 127.0.0.1 only, as in the documentation; when Dunree runs on another machine publish it on an address Dunree can reach and keep it off the internet.

2. Create the bouncer key
sudo cscli bouncers add dunree-$(hostname)

Prints the key once; copy it at once. Run it where CrowdSec runs (inside the container for Docker; the documentation page for Docker does not show the exact command for that, so it is not given here). Use a different name for each Dunree instance.

3. Paste address and key

In the Connection card below enter the LAPI address (the documentation examples use http://127.0.0.1:8080) and the key, press Test connection, then save. Leave the mode on Log only until the recent matches look right.

Optional: let CrowdSec read Dunree's request logs

This step is optional. CrowdSec has no built-in parser for the log type dunree, so without a parser of your own (see the CrowdSec guide) the lines are read but not understood and no scenario fires. The community blocklist and every other decision your LAPI holds work in Dunree without this step. Dunree writes one file per month named zr_<year>-<month>.log (for example zr_2026-9.log, no leading zero) in its log folder.

Option A. CrowdSec installed from packages
sudo mkdir -p /etc/crowdsec/acquis.d
sudo tee /etc/crowdsec/acquis.d/dunree.yaml >/dev/null <<'EOF'
filenames:
  - /path/to/your-dunree-log-folder/zr_*.log
labels:
  type: dunree
EOF
sudo crowdsec -t && sudo systemctl restart crowdsec

Replace /path/to/your-dunree-log-folder with your Dunree log folder (default ./log next to the Dunree program; use its full path). The last line checks the configuration and restarts CrowdSec, as in the documentation.

Option B. CrowdSec in Docker
# ./crowdsec/acquis.yaml   (mounted at /etc/crowdsec/acquis.yaml by the compose file above)
filenames:
  - /var/log/dunree/zr_*.log
labels:
  type: dunree

The path in this file is the one inside the container (where the compose file mounts your log folder), not the path on the host. Then run docker compose up -d (recreates the container).

Which decisions to act on

Decisions come from different sources. By default all of them follow the mode above. Keep a source on Log only to watch it without blocking, or ignore it. These choices can only make Dunree block less, never more.

  • Your own CrowdSec scenarios Addresses your CrowdSec caught misbehaving in your logs (origin "crowdsec").
  • Bans added by hand Added with cscli or with the ban tool at the bottom of this page (origin "cscli").
  • Community blocklist Addresses reported by other CrowdSec users worldwide (origin "CAPI"). Usually the largest group.
  • Blocklists you subscribed to Third-party lists from the CrowdSec console (origin "lists:name").
  • Anything else Decisions from the console or another tool.
